# 관리자 페이지 이벤트 분석 · 검토안

상태: 기존 검토안을 반영한 P1 로컬 구현·검증을 확인했다(2026-11-17). 이번 검토는 기존 미커밋 변경을 보존한 검토·검증·로컬 커밋 범위이며 화면 범위를 확대하지 않는다. main 병합·운영 배포 승인과 구분한다. [수집·조회 API와 검증 범위](all-page-events.md)를 따른다.

- 기존 관리자 레이아웃/폰트/색상 유지. 메뉴 `페이지 이벤트 분석`, 경로 `/admin/events`.
- 탭 `이벤트 로그` / `페이지 방문` / `이동 흐름` / `미션 퍼널`.
- 기간 필터 `시작일(KST)` / `종료일(KST)`는 종료일 포함, 최대 31일. 오늘은 조회 시점까지 고정하고 새로고침으로 갱신한다.
- 로그 필터 `페이지` / `이벤트 유형`, 버튼 `조회` / `새로고침`. 다른 탭은 기간 전체 지표임을 안내한다.
- 원시 로그 열: 서버 기록 시각 / 화면 ID·화면명 / 이벤트 유형 / 미션·단계 / 참가자(P-내부ID) / 세션(자격 증명이 아닌 digest 접두사). 서버 완료 발생 시각은 기록 시각과 구분한다. 최신순, 50행 서버 페이지네이션 `이전` / `다음`.
- 페이지 지표: 총 방문 / 고유 방문자 / 기간 내 재방문자. KST 일자별 방문·고유 방문자 추이.
- 이동 흐름: 직전 관측 화면 → 도착 화면, 이동 횟수·고유 사용자. 정확한 직전 이벤트가 없는 연결은 추정하지 않으며 상위 20개만 표시한다.
- 미션 퍼널: 다섯 미션의 단계별 고유 사용자, 진입 대비/직전 단계 대비 전환율, 직전 대비 이탈 추정. 분모 0은 `—`. SYNC 질문 상세는 기존 `/admin/funnel` 링크로 이동한다.
- 개인 검색·다운로드를 추가하지 않는다. 관리자 권한이 확인되기 전에는 분석을 요청하거나 표시하지 않는다.

고정 안내 문구:

> 화면 이벤트는 최선형 수집으로 누락될 수 있어요. 마지막 관측 단계는 실제 이탈·포기 확정이 아닙니다. 전환율은 기간 내 단계별 관측 인원의 비율이며 동일 회차의 순차 코호트를 뜻하지 않습니다.

> 로그인한 일반 참가자만 수집합니다. 인증 전·관리자·개발 미리보기·자동화 브라우저는 제외합니다. 새 페이지 기록은 수집 시작 이후만 조회할 수 있고, 기존 SYNC 질문 기록은 별도 수집 시작일부터 제공됩니다.

상태 문구:

- 로딩: `이벤트 분석을 불러오고 있어요.`
- 빈 데이터: `조회 기간에 수집된 이벤트가 없어요.`
- 오류: `이벤트 분석을 불러오지 못했어요.` / 버튼 `다시 불러오기`.

운영 빌드의 360/390/430/768/1440px에서 표·필터·페이지 이동·로딩/빈 데이터/오류·권한 거절을 검사하고 네 탭의 스크린샷을 확인했다. `test:page-events-ui`와 기존 `test:admin-ui`는 통과했다. P1 로그/방문 렌더 검사기는 FAIL/WARN 0개이며 기존 SYNC 공통 시트 하단 여백 WARN 1개는 별도다. 브라우저 API 응답은 격리된 합성 데이터로 실제 서버/DB·운영 권한 검증을 대신하지 않는다.
