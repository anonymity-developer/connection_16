# 행사 당일 장애 대응

실명·비밀번호·OTP·전체 태그 URL·세션/토큰을 문의 채널이나 로그에 붙이지 않는다. 운영자 UI에서 제공하는 승인/거절/숨김 이외의 수동 DB 수정·재지급·초기화는 하지 않는다.

| 증상 | 가능한 원인 | 안전한 확인 | 운영자 대응 | 개발자 확인 |

운영 재시작은 승인된 담당자의 기존 절차를 따른다. Work의 opt-in 장애 검사는 새 테스트 컨테이너 pause/unpause일 뿐 실제 서버 재시작 검증이 아니다. 서비스 프로세스 재시작 후 최종 완료 기록·콘텐츠·공식 시도가 보존되는지와 Redis 재시작에 따른 재로그인은 별도 격리 환경에서 검수한다.
