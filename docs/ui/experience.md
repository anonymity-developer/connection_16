# 개발용 5개 미션 체험 및 공통 UI

2026-11-09. 기준은 최신 통합·인증 DM + 소원 호수 증분까지 적용한 소스(tree `3e0c58ddee1048574d0ed9769ed7c2e557ae7085`). 운영 데이터·DB/API·인증·NFC·검수·지급·시상 계산은 바꾸지 않는다.

## 실행과 격리

`npm --prefix frontend run dev` 후 `/experience.html`. 기본 포트라면 `http://127.0.0.1:5173/experience.html`이다. Docker의 production 웹 컨테이너에는 이 개발 entry를 넣지 않는다. 모든 체험 화면은 `개발용 미리보기 · 실제 저장 없음`을 표시한다.

- `ExperienceApp`은 `import.meta.env.DEV`에서만 mount한다. 별도 HTML entry이며 기본 production index/App 라우트에 연결하지 않는다.
- 실제 AuthProvider/ParticipationProvider를 가상 사용자로 속이거나 전역 API/fetch를 교체하지 않는다. 실제 미션 화면은 기존 서버 port를 쓰는 wrapper를 유지하고, 별도 개발 entry만 동일 View에 메모리 port를 전달한다.
- `experience-store`는 DEV 확인 후 새 메모리 상태를 만든다. fetch·storage·쿠키·실제 토큰·인증정보·DB가 없다. HTML의 connect-src/form-action은 none이다. Vite HMR 연결이 막힌다는 경고가 날 수 있으나 앱 API를 허용하는 식으로 바꾸지 않는다.
- 가상 초기화는 이 메모리만 버린다. 기존 Docker 볼륨/사용자 계정/실제 기록을 조작하지 않는다. 브라우저 새로고침 시 가상 데이터가 초기화된다.

운영 wrapper의 서버 호출과 refresh는 그대로다. 프로필 자동 S, 실제 설문 결과/추천, 공식 게임 이상 입력 판정 및 동시성은 기존 백엔드가 결정한다. 가상 체험의 계산 결과는 공식 판정이나 성능 검증을 대체하지 않는다.

## 분수 설계 범위

- 기존 A 캐릭터 에셋을 조형물로 사용하고 석재 단·물길·분수 수반을 추가했다. 새 마스코트나 로마 조각상을 만들지 않는다.
- 운영 화면은 분수 그림·익명 소원 탐색·구름 보기를 공유한다. 운영에서 동전 던지기를 누르고 서버가 소원을 저장하면 분수 위에 동전이 안착하고 A가 지급된다.
- **동전 발급 후 직접 던지기, 동상 안착/물속 낙하 구분은 이번에는 개발 체험 전용이다.** 운영 API의 landingZone은 선택 운 점수용 필드이며 동상 안착을 뜻한다고 해석하지 않는다. 이를 실제 기록으로 저장하거나 다른 참가자에게 정확한 제출 위치로 재현하는 기능은 구현하지 않는다. 별도 계약·의미·운영 승인이 필요하다.
- 개발 체험은 드래그 끝 지점이 중앙 조형물 영역이면 안착, 나머지는 낙하로 연출한다. 키보드·터치 대안 버튼으로 두 결과를 선택할 수 있다. 두 방식 모두 가상 접수 성공 시 A가 지급된다.
- 분수 위에 안착한 자신의 동전은 화면 연출로 표시한다. 공개 feed에는 승인 전 들어가지 않는다. 물속 동전은 잠긴 뒤 물결로 표현한다.
- 분수에는 공개 소원을 한 번에 최대 10개 표시한다. A 앞에는 최대 3개의 금빛 동전이 쌓이고, 나머지는 물속에서 천천히 움직이는 그림자로 보인다. 동전이나 그림자를 누르면 소원과 댓글을 볼 수 있다. 개발 체험에서만 내 동전의 안착 위치를 연출한다.
- 동전이나 구름을 선택하면 인라인 전문과 기존 댓글을 연다. 운영 분수에서 더 오래된 소원을 불러오면 다음 동전 묶음으로 이동하고, 구름 보기에서는 기존 소원 뒤에 이어서 표시한다.

## 표시 문구·수집판

모델의 확정 이름/설명/독려 문구를 홈·미션 상세·체험에서 재사용한다. 내부 MAKE_A_WISH/SAY_SOMETHING과 slug/API는 유지한다. 미획득 캐릭터도 색을 살리되 잠금/진행/체크·점선 테두리로 상태를 구분한다. 완료만 반짝임을 갖는다. 말풍선은 `우리를 찾아봐!`. 전체 응원 문구 3개는 자동 반복 대신 사용자 버튼으로 바꿔 읽을 수 있다.

## 검증과 한계

ESLint/TypeScript/Vite build 및 기존83+신규11=94개 PASS. 신규 검사는 메모리 흐름·타이머 경계·멱등·익명 공개 분리·댓글/하트·실제 React 홈 SSR·DEV 진입 분리를 확인한다. 실제 게임 클릭/터치·CSS 배치·애니메이션의 브라우저 검증은 아니다.

`frontend/scripts/check-experience-ui.mjs`에 실제 5초+10초 플레이, 클릭·키보드·터치, 프로필/설문, 두 착지·댓글·하트·반응형·API 호출 차단 검사를 작성했다. Work의 Playwright는 Chromium 실행 파일이 없어 시작 실패했다. 원격 브라우저도 localhost:4495에 ERR_CONNECTION_REFUSED여서 실제 화면·스크린샷은 NOT_VERIFIED다. 시각적 완성도와 모바일 조작 품질은 실기기 검수 후 판단해야 한다.

가상 NFC로 각각의 미션을 연다. SHOW ME는 태그 없이 프로필 저장으로 참여한다.
