# MAKE A WISH 종이배 소원 호수

2026-11-15 기준 구현이다. 기존 콘텐츠 슬롯·revision·공개 피드·댓글 API와 1인 1소원 정책을 재사용한다. 현재 정책은 직접 공개이며 별도 검수 승인을 기다리지 않는다.

## 호수와 탐색

- 호수에는 화면 폭에 따라 서로 다른 색·크기·위치의 종이배 5~7개를 표시한다. 정적 SVG 호수와 CSS 둥실거림·반짝임만 사용하며 Canvas나 물리 엔진은 사용하지 않는다.
- 종이배를 누르면 소원 본문, 기존 댓글, 댓글 입력을 같은 상세 UI에서 연다. 모바일은 하단 시트, 넓은 화면은 중앙 대화상자를 사용한다.
- `새로운 소원 만나기`는 현재 세션에서 본 소원을 우선 제외해 다음 묶음을 보여준다. 불러온 항목을 다 보면 기존 커서로 다음 페이지를 요청하고, 전체를 소진한 뒤에만 다시 순환한다. 이 기록은 브라우저를 닫거나 새로고침하면 사라진다.
- `소원 목록`은 같은 공개 항목을 읽기 쉬운 카드로 보여주며 기존 커서의 `소원 더 보기`로 점진 로딩한다. 호수와 목록은 동일한 상세·댓글 UI를 연다.
- 공개 이름·프로필 연결과 익명 표시는 기존 API 응답 정책을 그대로 따른다. 레거시 운 점수와 낙하 구역은 표시하지 않는다.

## 작성과 완료

- 작성 폼은 호수 아래에 붙이지 않고 `내 소원 띄우기`로 여는 별도 대화상자/모바일 하단 시트에 둔다. 400자, 익명/공개 선택, 1인 1슬롯과 같은 슬롯 수정 규칙은 유지한다.
- 저장 성공 응답을 받은 경우에만 종이가 접혀 종이배가 되어 호수로 이동하는 짧은 CSS 연출을 재생한다. 실패·단순 재조회·같은 revision 재응답에는 성공 연출을 만들지 않는다.
- 미션 완료와 A 획득은 기존 서버 응답만 따른다. 종이배 위치나 애니메이션 상태를 권한·완료 근거로 사용하지 않는다.
- `prefers-reduced-motion`에서는 이동 애니메이션을 없애고 완료 상태 문구와 정적 종이배를 유지한다.

## 성능과 검증

- 호수는 컴포넌트 내부 SVG, 종이배는 작은 SVG와 CSS transform으로 그린다. 한 묶음은 최대 7개이며 세션 탐색 상태는 컴포넌트 메모리에만 둔다.
- 실제 참가자 화면과 관리자 메모리 미리보기, 네트워크 없는 개발 체험은 같은 호수·목록·상세·댓글 컴포넌트를 재사용한다. 미리보기 데이터는 실제 API나 참가자 기록에 쓰지 않는다.
- 프론트 lint/build/단위·콘텐츠·관리자·개발 체험 브라우저 검사와 360/390/430/1440px 화면 검토를 수행한다. 백엔드는 신규 소원에 레거시 운 값을 생성하지 않는 통합 검사를 포함한다.
