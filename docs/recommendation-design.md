# 가산점 기반 동료 추천 — weighted-v2

## 목적과 경계

공통 관심사·성향·교류·새로운 만남을 하나의 점수로 합산한다. 특정 조건의 존재만으로 나머지 조건을 무조건 앞서는 사전식 정렬을 대체한다. 최대 12명을 반환하며 추천 인원별 할당이나 친구/인기도 순위는 만들지 않는다.

후보 자격은 기존 탐색과 동일하다. 본인을 제외한 ACTIVE 계정, 가져온 프로필과 닉네임, 현재 참여/공개 동의가 필요하다. 관심사와 성향 결과가 없는 계정도 후보가 될 수 있다. 태그 해금은 추천 조건이 아니다.

## 점수 정책

| 신호 | 점수 | 조건 |
| --- | ---: | --- |
| 관심사 | 0~30 | `30 × 교집합 크기 / 합집합 크기`; 합집합이 비면 0 |
| 성향 | 20 | 같은 설문 버전·같은 저장된 유형 |
| 소원 댓글 | 15 | 두 계정 사이에 현재 유효한 소원 댓글 관계가 하나 이상 있음 |
| 응원 하트 | 10 | 두 계정 사이에 현재 유효한 응원 하트 관계가 하나 이상 있음 |
| 미방문 | 20 | 조회자가 상대 프로필을 아직 열지 않음 |
| 다른 반 | 5 | 가져온 지역·반 조합이 다름 |

최대 100점이다. 내부 계산은 0.01점 단위 정수(0~10000)이며 관심사 항목의 소수점 아래 두 자리 미만은 버린다. 부동소수점 오차로 동점을 처리하지 않는다. 가중치·기준 계산기·SQL 식은 `RecommendationPolicy`에 두고 변경 시 정책 버전을 올린다. 기준 계산기는 단위/SQL 대조 검사에 사용하고 실제 후보 정렬은 MySQL이 수행한다.

하트와 댓글은 방향에 관계없이 각각 한 번만 가산한다. 반복 댓글, 하트 취소/재등록, 여러 글에 남긴 반응은 같은 종류의 점수를 추가하지 않는다. 익명·공개 여부는 내부 점수에 영향을 주지 않는다. 연결된 글과 댓글은 현재 공개·승인된 revision이 있어야 하며 숨김·보관·미승인 근거는 제외한다. 상대가 비활성화되면 후보에서 제외되고 재가입한 새 계정은 이전 ID의 관계를 승계하지 않는다.

성향 미참여는 0점이며 불일치와 같은 값이다. 선택 정보가 적은 계정의 점수를 별도로 100점으로 재정규화하지 않는다. 관심사 합집합 비율은 많은 항목을 선택하는 것만으로 공통 개수에서 유리해지는 현상을 줄이지만, 희귀 관심사나 선택 개수에 따른 모든 편향을 해결하는 것은 아니다.

## 동점과 추천 묶음

정렬은 **총점 내림차순 → `SHA-256(정책 버전:조회자 ID:seed:후보 ID)` 오름차순 → ID 오름차순**이다. ID는 해시 충돌 시에만 최종 순서를 정한다. 가입 순서·개별 신호를 동점 우선순위로 다시 사용하지 않는다.

`GET /discovery/recommendations?seed=...`는 선택적인 1~64자 ASCII 영숫자/`_`/`-` seed를 받는다. 생략 시 `initial`을 사용해 기존 호출과 호환한다. seed는 인증/보안 토큰이 아니며 조회자를 지정하거나 점수를 바꿀 수 없다. 잘못된 값은 400 INVALID_RECOMMENDATION_SEED다.

추천 화면의 ‘다른 동료 추천받기’는 새 UUID seed를 URL에 기록한다. 같은 seed와 같은 데이터에서는 새로고침·브라우저 뒤로가기에도 순서가 같다. seed 교체는 동점 후보만 바꾸므로 반드시 새 사람이 나오거나 12명이 모두 교체되는 것은 아니다. 방문/관심사/계정 상태가 바뀌면 같은 seed에서도 점수와 후보가 달라진다. 최근 방문 시각·노출 이력·감쇠는 이번 버전에 추가하지 않는다.

## 저장소와 공개 정보

1. 인증·본인 자격 확인 후 SQL에서 후보별 스칼라 신호와 총점을 계산해 상위 12개 ID를 선택한다.
2. 선택된 ID만 기존 공개 Person 조회로 묶어서 읽고, 앞에서 계산한 순서를 복원한다. 관심사 JSON과 설문 정의를 전체 후보에게 먼저 구성하지 않는다.
3. Person DTO는 기존 필드를 유지한다. 실명·반·연결된 글·익명 작성자·교류 신호·점수·순위 근거를 추가하지 않는다. 화면 이유는 공개된 공통 관심사/성향/방문 정보만 사용한다.

추천 저장소 SQL은 후보가 있으면 2회, 없으면 1회다. 이는 세션·본인 자격 조회를 제외한 코드 경로 기준이며 쿼리 수가 기존보다 감소했다는 뜻은 아니다. 후보 수 C에 대한 점수 정렬과 상관 서브쿼리의 비용은 남아 있다. 기존 PK/인덱스를 사용하고 새로운 캐시·DDL·Redis 키는 추가하지 않는다.

추천 조회와 seed 교체는 방문/친구 관계를 저장하지 않는다. 방문은 기존 명시적 POST open에서만 생성한다. 공개 그래프의 점수는 별도 `RelationshipWeight`를 사용하며, 추천 총점이나 익명 반응으로 그래프 간선/굵기를 만들지 않는다. 순위 변화 자체가 활동을 추측하게 할 가능성까지 없애는 익명성 보장은 하지 않는다.

## 검증과 향후 측정

- 단위 검사: 최대/최소, 빈 관심사, 합집합 비율, 가산 효과, 잘못된 집계 입력.
- 실제 MySQL: 고정 난수 256개 신호 조합에서 기준 계산과 SQL 점수의 일치.
- 실제 MySQL/Redis 서비스 검사: 관심사와 다른 반의 합이 하트를 이기는 사례, 관심사 과다 선택, 댓글 반복 상한, 반응 양방향, 숨김/보관/미승인 제외, 후보 제한 전 정렬, seed 재현/교체/검증, 비활성 상대 제외, 익명 DTO/그래프 격리.
- 운영 빌드 브라우저: seed 전달/URL 복원, 추천 버튼, 비로그인 게이트, 기존 검색·상세·관계 동작과 5개 화면 폭.

추천 품질과 속도 개선 수치는 아직 측정하지 않았다. 후속 비교에서는 같은 데이터 분포·장비·동시성에서 후보 수, API p50/p95, SQL 시간/EXPLAIN ANALYZE, 추천 반복률과 새로운 동료 열람률을 측정한다. 품질 지표를 위해 노출 기록을 수집하려면 보관 범위와 계측을 별도로 설계한다. 이 버전의 재현 가능한 정책/검사는 그 비교의 기준이며 성능이나 연결률 향상을 입증한 결과가 아니다.
