# 검수 없는 공개와 관리자 게임 초기화

2026-11-11 사용자 요청으로 적용하는 현재 동작이다. AI·관리자 검수는 기본 비활성이며, 이전 비동기 검수 코드는 향후 명시적으로 켤 때만 사용한다.

## 제출과 공개

- 소원·응원·댓글은 기존 인증·CSRF·기간·프로필/동의·해금·본문/스타일·멱등성 검사를 통과하면 같은 트랜잭션에서 즉시 공개한다. `APPROVED`는 이 모드에서 공개 가능한 버전이라는 뜻이며 AI나 관리자가 검수했다는 뜻이 아니다. 새 검수 job이나 외부 호출을 만들지 않는다.
- 수정도 즉시 공개 버전을 바꾸며 이전 불변 revision은 남긴다. 글자 지급·공개 상태·시상 집계는 여전히 별도 데이터다. 관리자에게는 검수 대기 대신 콘텐츠 숨김/복구와 감사 이력을 제공한다.
- FAST TAP은 서버에서 정상/무효/중단/만료를 바로 결정한다. 1ms 이상 간격과 200회 초과는 허용한다. 1ms 미만의 중복 입력은 `INVALID / DUPLICATE_MILLISECOND`로 자동 무효 처리하며 기록은 저장하고 F는 지급하지 않는다. 최대 1000개, 10초 범위와 순서·중단·접수 기한 검사는 유지한다.
- 기존 검수 대기 글은 원래 접수와 현재 슬롯을 확인해 검수 없이 게시 버전으로 전환한다. 운영자가 숨긴 글은 숨김을 유지하며 대기 작업만 닫는다. 기존 `REVIEW_REQUIRED` 탭은 원본 입력·해시·횟수·접수 기한을 재검증해 자동 판정한다. F는 OPEN·현재 참가 자격·기존 해금과 실제 접수 근거가 충족될 때 공통 완료 경로로 지급한다. 새 입력이나 접수 시각을 만들지 않는다.
- 기본 2초 주기의 `DirectPublicationWorker`는 이전 대기분만 정리한다. 새 제출의 공개는 이 worker를 기다리지 않는다. `tagme.content.worker-enabled=false`에서는 이전분 자동 정리도 멈춘다. 별도 환경값을 채울 필요 없이 `tagme.moderation.enabled=false`가 기본이다.
- 검수 모드를 나중에 다시 사용하려면 별도 정책 검토 후 `tagme.moderation.enabled=true`와 제공자를 명시한다. 현재 UI·기본 설정은 검수 없이 사용한다. 기존 검수 통합 테스트는 이 옵션을 명시해 보존한다.

## 관리자 소프트리셋

`/admin` → **참가자** → 참가자 상세 → **게임 재참여 / 게임 참여 초기화**에서 한 명씩 실행한다. 대상과 사유를 확인하고 확인란에 `초기화`를 입력한다. 전체 참가자를 한 번에 초기화하는 동작은 없다.

| 유지 | 현재 참여에서 초기화 |
| --- | --- |
| 계정·비밀번호·가입 순서·로그인 세션 | 네 게임의 현재 결과·작성 슬롯·완료 근거 |
| 프로필·관심사·공개 동의·첫 S | 성향 결과, 탭 공식 기회, 소원·응원 |
| 기존 태그 해금과 원래 해금 시각 | 본인이 남긴 댓글·하트의 현재 반영 |
| 접속 이력·프로필 방문과 동료 관계 | 현재 미션별 순위와 전체 완료 순서 |

이미 해금한 게임은 참가자가 새로고침한 뒤 바로 재참여한다. 한 번도 태그하지 않은 게임은 계속 LOCKED다. 전체 완료 순번의 전역 sequence는 되감지 않으며 다시 모두 완성하면 새 순번을 부여한다. 다른 참가자의 계정·독립 소원/응원은 초기화하지 않는다. 보관된 원글에 달린 댓글·하트는 새 원글로 옮겨 붙이지 않는다.

수집판의 획득·전체 완료 연출 확인 기록도 초기화 회차별로 구분한다. 유지된 첫 S를 다시 획득한 것처럼 연출하지 않고, 새로 참여한 네 글자와 전체 완성은 다시 한 번씩 확인할 수 있다.

이전 소원·응원·댓글과 탭 도전·입력 이벤트는 `archived_at`을 남겨 보관한다. 성향 결과·완료 순서·완료 근거·현재 슬롯·내 하트는 삭제 전 `game_participation_resets.snapshot_json`에 원본을 보관하고 현재 projection에서 제거한다. 접수 시각은 마이크로초가 보존되는 ISO 문자열로 보관한다. 계정·인증 비밀값은 snapshot에 넣지 않는다. 보관된 글은 일반 콘텐츠 숨김/복구 API로 재공개할 수 없다.

초기화 이력의 관리자·사유·시각·요약은 참가자 상세 최근 10건과 감사 이력에 남긴다. 원본 snapshot이나 비공개 본문을 초기화 API로 내보내지 않는다. 보관 이력의 자동 복원/내보내기/보관 기간 정리는 현재 기능에 포함하지 않는다.

## API와 동시성

`POST /api/v1/admin/members/{id}/reset-games`는 현재 서버 ADMIN, CSRF, `Idempotency-Key`(16~64자)가 필요하다.

```json
{"expectedGeneration":0,"reason":"개발 테스트 재참여","confirmation":"RESET"}
```

응답은 `{id,generation,actorId,reason,createdAt,summary}`다. 사용자·관리자 행을 ID 오름차순으로 잠그고, 원본 보관·현재 참여 초기화·감사를 같은 트랜잭션에서 처리한다. 실패하면 전부 롤백한다. 같은 키/대상/사유/이전 generation의 재전송은 최초 응답을 돌려주며 두 번 초기화하지 않는다. 다른 요청의 오래된 generation은 409다. ADMIN 계정 자체는 초기화 대상이 아니다.

`GET /missions/collection`과 관리자 참가자 상세는 `resetGeneration`을 반환한다. 네 게임과 댓글/하트 변경 요청은 `X-Participation-Generation` 헤더에 그 값을 보낸다(초기 0). 참가자 행 잠금 후 비교하므로 리셋과 경합한 이전 화면의 요청은 409 `PARTICIPATION_RESET`으로 거절한다. 헤더를 생략한 이전 클라이언트는 최초 세대 0으로 취급하며 리셋 후 새로고침해야 한다. 계정 전환 후 이전 계정의 늦은 응답으로 이 값을 덮어쓰지 않는다.

프론트는 응답 유실 시 동일한 키·본문으로만 재시도한다. 409는 현재 참여 상태를 다시 읽게 하며 401/403은 비공개 참가자 화면을 제거한다. 화면 확인 대화상자는 실제 운영 기능의 일부이며 인증·CSRF·서버 권한 검사를 대신하지 않는다.
