# 행사 종료 후 잠정 후보 검토 절차

1. 확정한 일정/동의/설문 설정이 실제 적용됐는지 먼저 확인한다. 여기 있는 문서로 행사 일정을 자동 설정하지 않는다.
2. 운영자 계정으로 /admin → **시상 후보**에 접근한다. 일반 계정/로그아웃은 후보를 조회할 수 없어야 한다. 실제 개인정보나 자격증명을 검수 자료/로그에 복사하지 않는다.
3. 제출 마감·검수 마감·조회 시각·기준 버전을 확인한다. 행사/검수가 진행 중이면 결과는 변동한다. 미처리 콘텐츠 검수는 기존 탭에서 처리하고 다시 조회한다.
4. 완료 근거 불일치/누락, 현재 자격 확인, FAST TAP 검토 대기 수와 내부 ID를 점검한다. 게임 판정 UI/재도전 정책은 이번에 추가하지 않았다. DB를 VALID로 직접 바꾸거나 완료 증거를 수동 INSERT하지 않는다.
5. 각 부문에서 후보의 **산정 근거 보기**를 열어 최초 프로필 시각, 실제 5개 접수 근거 종류/ID/인정 시각을 확인한다. 최초 완성상은 승인 순서나 completion_order로 결정하지 않는다.
6. 동점이면 프로필 최초 등록 시각을 비교한다. 시각은 한국어 초 단위 표시와 원본 UTC 정밀 시각을 함께 제공한다. 두 시각까지 같은 공동 순위는 운영 결정 전 보류한다.
7. 댓글왕은 다른 사람 소원별 중복 제거, 인기 응원은 현재 유효 하트(취소/자기 제외) 기준임을 확인한다. 0 활동과 숨김/철회/제재 변경은 별도 검토한다. 수정본 대기 때문에 기존 승인본을 임의로 제외하지 않는다.
8. 복수 부문 1위 후보를 확인한다. 1인 1수상·우선권 원칙은 유지하되 부문 선택/차순위 승계 정책이 확정되기 전 자동 배정하지 않는다.
9. 아래 미확정 정책을 확정하고 재현 가능한 스냅샷/정정/발표 감사 설계를 별도 승인한 뒤 최종 시상을 진행한다. 현재 UI에는 확정/공개/추첨/발송 버튼이 없다.

## 운영 결정 체크리스트

- [ ] 경쟁 점수와 최초 프로필 등록 시각이 모두 동일할 때 최종 동점 처리
- [ ] 여러 부문 1위의 부문 선택 방식, 유효 전체 완성 우선권과 차순위 승계의 적용 순서
- [ ] 0댓글/0하트/0탭 기록의 최소 활동 조건 및 수상자 부재 처리
- [ ] 랜덤 참여상 인원, 5개 완료/1개 이상 등 적격 조건, 중복 수상 제외, 추첨 고정·증빙 방식
- [ ] 최종 후보를 고정할 시각·규칙 버전·승인자, 발표 이후 숨김/철회/제재·판정 정정 영향
- [ ] 영구 스냅샷/최종 확정/정정 모델과 권한·감사·중복 요청 방지, 보존·파기 정책
- [ ] 게임 REVIEW_REQUIRED의 판정·재도전·이의 제기 운영 절차
- [ ] 기존 과거 데이터 중 published_at/완료 evidence 누락 처리 (임의 보정하지 않기)

## 로컬 화면 검수

360/375/390/412/430/1440px에서 네 부문 전환·정렬·근거 펼치기·이전/다음 후보·오류 후 재조회·긴 닉네임/시각 줄바꿈·키보드 포커스와 클릭 영역을 확인한다. 빈 데이터는 빈 상태여야 하며 숫자를 채우지 않는다. 관리자 권한 회수 후 재조회 시 데이터 패널이 사라지는지 확인한다. API/SQL 및 실렌더는 이번 Work에서 미검증이며 실제 테스트 실행을 마쳐야 한다.
