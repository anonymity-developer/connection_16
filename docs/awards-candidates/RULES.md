## 공통 자격과 시각

- 경쟁 네 부문은 **다섯 미션 전체 유효 완료자**만 대상이다. 단순 event_completions/collection 완료 개수만으로 추론하지 않는다.
- 현재 ACTIVE·공개·현재 정책 2개 동의, 기존 profileComplete의 MM 정보·닉네임·자격증명, 최초 프로필 등록 시각이 있어야 한다. 공개/하트/소원 댓글 원글의 유효성은 기존 공개 상태 조건을 별도로 사용한다. 하트를 누른 사람이 전체 5개 완료할 필요는 없다. 하트 제공자의 최초 프로필 시각을 후보 동점 조건과 혼동하지 않는다.
- 현행 저장 흐름에서 최초 프로필 등록은 profiles.published_at으로 읽는다. 스키마에는 별도 profiles.created_at이 없으며, 과거 비공개 프로필을 나중에 공개했던 데이터의 더 이른 생성 시각은 복원할 수 없다. 그런 과거 데이터가 있다면 운영 검토가 필요하다. 기존 프로필 저장은 최초 공개 시각을 COALESCE로 유지하므로 수정/다시 공개해도 바뀌지 않는다. users.created_at(가입), updated_at(수정), 최근 PROFILE receipt를 대신 사용하지 않는다. 이 값이 누락된 과거 데이터는 수상자를 임의 선택하지 않고 자격 확인 대상으로 표시한다.
- 점수/유효 완성 시각과 최초 프로필 시각까지 같으면 공동 순위·추가 결정 필요를 표시한다. user_id는 표시 순서를 안정화할 때만 사용하며 동점을 해소하지 않는다. receipt_order는 근거 식별만 한다.
- 첫 SHOW ME의 PROFILE 근거는 이후 프로필 버전이 증가해도 보존한다. 신규 자동 지급의 실제 accepted_received_at을 그대로 사용하며 행사 시작/사전 등록 시각으로 소급하지 않는다. 과거 유효 TAG_UNLOCK 근거도 역사 기록으로 읽는다. 이 기능은 지급 기록 자체를 변경하지 않는다.
- 콘텐츠는 최초 승인된 원본 근거가 현재도 APPROVED이고 공개 허용된 슬롯이어야 한다. 수정본 검수 대기 중에는 기존 승인본을 사용한다. 새 승인본으로 교체돼도 원래 최초 유효 승인 근거의 접수 시각을 유지한다. 반려 원문 시각을 수정 승인본이 상속하지 않는다.
- 접수/인정은 행사 opens_at 이상, submit_closes_at 미만. 완료 처리는 moderation_closes_at 이내이고 미래 시각 기록은 제외한다. 실제 마감은 DB 설정만 사용한다.
- 현재 비공개/동의 철회/제재/숨김에 따라 후보가 바뀐다. 이미 확정된 시상을 소급 변경하는 기능은 아니다. 현행 코드에 탈퇴·댓글 취소가 별도 상태로 없으면 기존 숨김/반려/승인 포인터/하트 삭제 상태로 판단하며 가상의 취소 컬럼을 만들지 않는다.
- 0댓글/0하트 기록은 0 그대로 보여준다. 미확정된 최소 활동 조건을 임의 추가해 자동 탈락/수상 처리하지 않는다. UI는 점수 0에 운영 확인 안내를 붙인다.

## 일관성·보안

`OperationsService.awards`는 현재 credential version/DB ADMIN을 검사하고, 기존 관리자 락 이후 하나의 REPEATABLE_READ 트랜잭션 안에서 모든 근거와 부문을 계산한다. 외부 API 호출/추첨/DB 쓰기는 없다. 조회마다 현재 상태를 반영하며 기록이 같으면 후보 순서가 같다. observedAt은 조회 시각이며 영구 스냅샷 ID가 아니다. 운영 변경이 있으면 다음 조회 결과가 바뀌는 것이 정상이다.

GET /api/v1/admin/awards?category=FIRST_COMPLETION&offset=0&limit=20 (다른 부문 COMMENT_KING/POPULAR_CHEER/FAST_TAP). limit 1~50, offset 0~100000. 실제 역할·세션 버전 검증은 서비스에도 있고 Spring Security의 /admin 권한과 no-store를 유지한다. 응답에는 닉네임/내부 ID·점수·근거 ID/시각만 포함하고 본문·실명·MM 아이디·토큰·설문 답·tap payload는 포함하지 않는다. 검토 목록은 최대 50개이고 전체 건수를 따로 표시한다.

1인 1수상은 중복 후보 플래그로 드러낸다. 여러 부문 1위일 때 어느 상을 배정할지 확정되지 않았으므로 자동 순차 배정이나 차순위 승계를 구현하지 않았다. 후보 수에 맞춰 가상의 수상자를 만들지 않는다.
