# TAG ME 4차 폴리싱 - 3차 위 추가 적용

기준: `86ad1dd` + 1·2차 통합 + 3차 friendly UI. 기존 3차 ZIP의 전체 통합 패치를 별도 `work/ssafy-ui-v4` worktree에 적용한 뒤 수정했다. 이전 ZIP/작업 공간은 그대로다. commit/push/PR/merge/배포 및 실서버 접속 없음.

## 글자 에셋과 표현

- 사용자 제공 개별 S/S/A/F/Y를 바탕으로 배경 분리·가장자리 정리 후 320×400 투명 WebP 다섯 개를 만들었다. 명찰/연결 신호/별/번개/하트는 유지했다. PNG 원본과 참고 시트는 전달 ZIP의 `source-assets/`에 보존한다.
- 배경 분리에는 이미지 편집 도구를 사용했으며 일부 가장자리/표정이 정리 과정에서 재렌더되었다. 원본 픽셀을 그대로 자른 결과라고 주장하지 않는다. 이후 분리·작은 잔여 영역 제거·무손실 WebP 인코딩은 정해진 크기로 일관되게 처리했다. 원본 이미지 자체는 수정하지 않았다.
- 웹 에셋 크기는 각 61~78KB, 전체 약 339KB이다. 레퍼런스의 흐릿한 중복 글자·넓은 여백은 포함하지 않았다. 별도 사람/태그 요정은 만들지 않았다. 공식 SSAFY 자산으로 표시하지 않는다.
- 수집판은 기존 `COMPLETED`일 때만 컬러·작은 반짝임을 표시한다. 미획득은 회색과 기존 잠금/진행 표시를 유지한다. 미션 카드의 컬러 그림은 해당 미션의 대표 이미지이며 보상 획득 표시가 아니다.
- 실제 완료 상태(미리보기 제외)에는 CSS 1회 축하 애니메이션만 적용한다. 기존 성공 조건과 지급 로직은 변경하지 않았다. 첫 S 프로필의 이미지는 '목표 글자' 안내다.

## 겨울과 문구

작은 정적 눈송이·반짝임을 히어로의 그림 영역과 수집판 테두리 바깥에만 배치했다. 화면 전체 눈/파티클은 없다. `polish.css`의 `--winter-display: none` 또는 `<html data-winter="off">`로 끈다. `prefers-reduced-motion`은 축하 움직임도 제거한다.

홈 소개는 '태그 한 번, 우리 사이 한 걸음.'으로 줄였다. 로그인 전 수집 안내/현장 태그 안내/CTA를 축약하고, 중복된 '해금→참여→획득' 설명 하나를 제거했다. 소원·응원 승인 후 지급 안내, 재인증/태그 연결 15분, 프로필 조건/동의/개인정보 공개, 인증 오류·만료 안내는 유지했다. 로그인·회원가입 파일은 3차와 동일하다. 추천 이유는 기존 서버 필드로 만든 짧은 배지로 바꿨다.

## 추천/가중치 코드 확인 결과 - 알고리즘 변경 없음

| 항목 | 실제 구현과 근거 |
| --- | --- |
| 추천 후보 산출 | `DiscoveryRepository.SELECT`: `common_count`는 본인/후보 공통 interest ID 수, `same_type`은 유형 코드와 질문 버전의 일치 여부 |
| 추천 순위 | `DiscoveryRepository.recommended`, 59행: `ORDER BY visited ASC, common_count DESC, same_type DESC, u.id DESC LIMIT 12`. 미방문을 먼저, 공통 관심사 수, 같은 취향 여부, ID 순으로 정렬한다. **방문/하트 합산 교류 점수는 추천 순위에 사용하지 않는다.** |
| 그래프 교류 점수 | `RelationshipWeight.score`, 6~8행: 내가 방문 1 + 나를 방문 1 + 상호 방문 추가 2 + 내가 누른 공개 응원 하트 2, 최대 6. 반복 활동을 누적하는 점수가 아닌 현재 여부 조합이다. |
| 실제 반영 | `DiscoveryRepository.graph`, 95~98행에서 edge의 weight/strength를 만든다. 노드 목록은 ID 순이며 가중치 순위가 아니다. `NetworkFigure`, 13~15행은 weight를 `relationshipPresentation`으로 넘겨 실제 선 너비를 1.5/2.5/4px로 표시한다. |
| 프론트 추천 순서 | `Discovery.tsx` 19행은 응답 배열을 그대로 저장하고 목록에서 그대로 map한다. 재정렬 없음. API 요청/필터/페이지 처리도 변경 없음. |
| 추천 이유 | `sharedInterests`, `sameType`, `visited`에 따라 '공통 관심사', '같은 취향 유형', '아직 만나보지 않은 동료'를 표시. 숫자 점수나 새 사유를 만들지 않는다. |

근거 저장소: https://github.com/anonymity-developer/connection_16/blob/86ad1dd/backend/src/main/java/com/tagme/discovery/DiscoveryRepository.java

이는 코드 경로 확인 결과다. 운영 DB의 추천 분포/정렬 결과, 실제 이용자의 하트/방문 데이터와 연동 품질은 **미검증**이다. 이번 작업에서 백엔드 가중치/추천 알고리즘을 수정하지 않았다.
