# 행사 종료 후 운영 체크리스트

이 문서는 승인·추첨·삭제를 실행하지 않는다. 결과 화면은 잠정 검토용이며 `finalizationAvailable=false`다.

## 마감·검수·시상 검토

- [ ] 실제 event_settings의 제출 마감·검수 마감과 서버 UTC/표시 KST를 대조한다. 미설정/진행 중이면 종료 보고 수치라고 확정하지 않는다.
- [ ] 전체 미처리 검수 경고를 확인하고 기존 검수 화면에서 숨김·재검수·관리자 확인 필요 원본을 검토한다. 마감 후 판정 정책은 별도 승인한다.
- [ ] 행사 결과 화면의 scope·관찰 시각·지문과 미션별 고유 인원/글자 분포를 기록한다. 회원/활동/서버완성/시상적격 인원을 섞지 않는다.
- [ ] SHOW ME S 미지급·사전 등록 미지급, 유효하지 않은 근거, FAST TAP REVIEW_REQUIRED/EXPIRED/INTERRUPTED를 점검한다. 이 화면으로 재지급하거나 상태 변경하지 않는다.
- [ ] 네 시상 부문 후보/접수 근거/공동 순위/최초 프로필 시각/복수 1위를 검토한다. 기존 시상 화면과 조회 시각이 다르면 같은 결과라고 가정하지 않는다.
- [ ] 순번을 최초 완성 순위로 대체하지 않는다. 콘텐츠 승인 지연과 인정 접수 시각은 기존 시상 계산을 따른다.
- [ ] 다시 조회하여 수치·후보·제외 근거 변화와 자료 지문을 비교한다. 지문은 공식 확정 기록/감사 이력이 아니다.
- [ ] 승인권자·확정/정정 절차·중복 수상 배분·랜덤상 조건/인원·발표 시점을 문서로 확정한다. 이번 코드로 수상 확정/추첨/지급하지 않는다.
- [ ] CSV/JSON/MD의 후보 P-ID는 관리자용 가명 식별자다. 공개 자료에서는 제거하고 집계만 재검토한다. 소수 셀/시간대 재식별 위험도 확인한다.
- [ ] 보고서에는 관찰한 방문·댓글·하트를 기술한다. 인간관계 향상/행사 성공을 자동 주장하지 않는다.

## 개인별 활동 분석 활성화 전 승인

- [ ] 목적·법적/동의 범위·분석 담당자와 열람 권한·분석 기간을 확정한다.
- [ ] 실제 데이터 추출/반출 허용 범위와 최소 cohort를 승인한다. 현재 개인별 추출 경로는 없다.
- [ ] 분석기간별 HMAC 키 생성·안전 보관·폐기 주체, 기간 간 연결 여부를 결정한다. 키와 원본 내부 ID를 CSV와 함께 저장하지 않는다.
- [ ] MySQL 격리 테스트로 SQL를 검증하고, from<until<=observed UTC와 동일 읽기뷰를 보장할 승인된 실행 방법을 별도 구현·검토한다.
- [ ] staging internal_user_id/record_key 제거·가명 변환·금지 컬럼 검사·CSV 주입 방어를 실제 반출 직전에 검증한다.
- [ ] 현재 `activity_dataset.py` CLI는 내장 SYNTHETIC fixture 생성만 허용하며 운영 DB 주소·인증정보 옵션이 없다.

## 보관·접근 정리 — 자동 작업 없음

| 결정 항목 | 운영자가 확정할 내용 | 이번 구현 |
| --- | --- | --- |
| 보관 기간 | 계정/프로필/동의/콘텐츠/행동 근거/감사 로그별 기한과 근거 | 미확정; 삭제 안 함 |
| 삭제 대상 | 원본·가명 데이터·다운로드 사본·내보내기 파일·백업 | 대상/검증/담당자 승인 대기 |

| 새 행동 수집 | 페이지/스캔/체류/취소 이력 목적·안내·보관 | 구현 보류 |

운영자 개인 PC에 자료를 장기 방치하지 않는다. 외부 공유/Notion/개인 클라우드 전송은 승인된 목적·범위에 한해서 별도 결정한다. 이 도구는 자동 외부 전송하지 않는다.
