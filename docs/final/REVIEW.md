# 사용자 최종 검수 순서

정식 검수 전 파일 적용과 lint/build/unit를 끝낸다. 미승인 정책/일정/발신 자격증명을 임의로 입력하지 않는다.

1. **홈·수집판:** PC에서 우측 큰 안내 없이 수집판이 전체 폭인지 확인. S/S/A/F/Y 및 소개/취향/소원/탭/응원, 미확인·미획득·실제 획득 상태를 구분. 숫자/배지는 서버 기록이 있을 때만 표시. 전체 완료이면 완성 기록 링크 확인.
2. **카드:** 5개 캐릭터·정식 미션명·한 줄 설명 유지, 반복 ‘미션 알아보기’ 없음. Tab/Enter로 카드 전체 상세 진입. 소원·응원에만 검수 안내. 지도 카드가 별도 가이드이고 /missions가 열리는지 확인.
3. **다섯 상세·힌트:** 잠긴 상태에서 큰 안내 대신 짧은 NFC 안내. 주소 조회만으로 해금/수행 불가. 위치 기본 안내와 미션별 실제 조건 확인. 임의 층 없음. 향후 승인된 hint를 입력하면 기본 안내 대신 표시되는지 확인.
4. **모바일:** 360/375/390/412/430px와 PC. 가로 스크롤·글자 잘림·카드 터치·스크롤 길이·하단 내비·푸터 겹침 확인. 키보드가 입력/버튼을 가리지 않는지 실제 기기 확인. 모달 Escape/닫기/포커스 복귀·reduced-motion 확인.
5. **FAST TAP fixture:** 준비 취소 → 응답 유실 재시도 → 다른 탭 현재 도전 복원, 같은 tick 더블클릭, 실패 후 재시도, 페이지 재진입. 취소 답변만으로 새 기회나 완료를 만들면 안 됨. 현재 슬롯 조회를 우선. 실제 참가자의 공식 1회 기회를 테스트로 소모하지 않음.
6. **SHOW ME fixture/격리 DB:** 소개 없음/관심사 없음/정책 누락/태그 미해금이면 미지급. 모두 충족 시 최초 한 번. 프로필 수정/재로그인/태그 재접속 후 최초 완료/evidence 중복 없음. Java 회귀는 별도 실행 필요.
7. **운영 설정·관리자:** 인증 비활성·행사 NOT_CONFIGURED·정책 미설정은 현재 운영자 의도에 따른 상태. 이를 정상 운영 준비 완료로 오판하지 않음. 읽기 전용 감사 도구만 사용. 선택 운 점수 없음은 허용. 일반 계정의 운영 데이터 접근 차단, 관리자 검수/fence/감사·오류 복구를 격리 fixture로 검사.
8. **NFC 실기기:** 승인된 테스트 환경에서 같은 브라우저의 태그→로그인→프로필→복귀, 새로고침/뒤로가기/15분 만료 확인. Safari/Chrome/앱 내 브라우저·private mode의 쿠키가 공유된다고 가정하지 않음. HTTPS/secure context 차이도 확인. 실제 태그 토큰/OTP/쿠키는 외부에 공유하지 않음.
9. **시상:** 별도 ZIP/실제 구현 SHA 확보 전 통합 완료로 표시하지 않음. completionOrder는 운영 순번이며 최종 시상 순위가 아님. 규칙·후보·동점·취소·지급 idempotency를 실제 시상 코드로 별도 검증.

실행 스크립트:
- 기본: scripts/qa/Run-PrelaunchQA.ps1
- JDK21 + Docker: 위 스크립트 -Backend (fresh Testcontainers, 실제 MM mock)
- Playwright: 위 스크립트 -Browser (기존 7개 계약 + check-polish-ui의 6개 너비)
- 로컬 설정 GET: node scripts/readiness/audit.mjs --probe http://127.0.0.1:8080

위 브라우저/기기/서버 항목은 이번 Work에서 실행하지 못했다. fixture PASS와 실제 운영 검증은 별도로 기록한다.

- 수집판: 미확인/미획득/검수 대기 때 공통 `나를 찾아봐!`가 하나만 보이는지, 부분 획득은 나머지만 회색인지, 전체 획득 시 말풍선이 사라지는지 확인. 360/375/390/412/430/1440px 및 텍스트 확대에서 꼬리·라벨·캐릭터 겹침/잘림 확인. 미션 카드·상세에는 말풍선 없음.
