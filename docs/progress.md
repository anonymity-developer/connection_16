# 페이즈별 개발 현황

이 파일은 다음 Codex 세션이 실제 진척을 복구하는 시작점이다. 설계 설명은 각 문서에 두고, 여기에는 실행/미완료/검증 결과만 적는다. 문서 추가나 스킬 설치를 기능 구현 완료로 세지 않는다.

## 2026-11-03 — 개발 환경 보충

- 사용자 요청으로 UI 구축에 `design-taste-frontend`를 사용한다. 현재 원본은 2.1.5이며 저장소 안 `.agents/skills`에 Playwright/gh-fix-ci와 함께 고정해 둔다.
- AGENTS 계층, 스킬/문서 라우팅, 출처/해시 lock, 환경 doctor와 Taste 실행 진입점을 추가했다. 사용법과 실제 실행 제약은 [Codex 환경](codex-setup.md)에 있다.
- 기존 프론트 초기 화면을 확장하는 작업이 진행 중이다. 홈/티켓형 수집판/미션 카드/인증 화면/대표 소원 화면이 있으나 **Taste 적용 전에 작성한 초안**이며 확정 디자인이 아니다.
- 초안은 `npm run lint`, `npm run build`를 통과했다. 브라우저/사용성 검증 전이므로 UI 페이즈를 완료 처리하지 않는다.
- Taste 원본 정적 lint도 실행했고 FAIL을 확인했다. 상단 장식 라벨/번호/장식 기호/정지 그림자 등이 지적됐다. 적용할 앱 화면 절차를 읽고 해당 화면 규칙으로 개선/재검사해야 하며 기존 ESLint 성공을 Taste 통과로 기록하지 않는다.
- 일반 로그인/가입/비밀번호 관리 API는 아직 없다. 프론트 초안의 입력 확인은 실제 자격증명을 전송/저장하거나 세션을 만들지 않는다.
- 로컬 브라우저 inspector는 Chromium socket 권한, Playwright CLI는 캐시/설치 부재로 실행이 막혔다. 다음 UI 작업에서 사용 가능한 브라우저 도구 또는 실행 가능한 환경으로 전후 캡처와 검사를 해야 한다.

## 이어서 할 일

1. 스킬 무결성과 doctor를 실행하고 해당 세션의 실제 실행 가능 도구를 확인한다.
2. Taste의 앱 화면 절차와 app-screens.md를 읽는다. 초안을 확정 브랜드로 취급하지 말고 전후 화면을 근거로 개선한다.
3. 운영 빌드의 모바일/태블릿/데스크톱, OTP 앞자리 0/붙여넣기, 비밀번호 표시/확인, 내비게이션, modal 포커스/Escape와 dev preview 배제를 확인한다.
4. UI 페이즈가 검증된 뒤 결과/제약과 커밋을 기록하고 페이즈 2 인증으로 진행한다. 인증 전에 비밀번호 정책/해시 비용과 Mattermost 실제 권한을 확정한다.
