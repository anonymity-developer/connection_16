# 페이즈별 개발 현황

이 파일은 다음 Codex 세션이 실제 진척을 복구하는 시작점이다. 설계 설명은 각 문서에 두고, 여기에는 실행/미완료/검증 결과만 적는다. 문서 추가나 스킬 설치를 기능 구현 완료로 세지 않는다.

## 2026-11-03 — 개발 환경 보충

- 사용자 요청으로 UI 구축에 `design-taste-frontend`를 사용한다. 현재 원본은 2.1.5이며 저장소 안 `.agents/skills`에 Playwright/gh-fix-ci와 함께 고정해 둔다.
- AGENTS 계층, 스킬/문서 라우팅, 출처/해시 lock, 환경 doctor와 Taste 실행 진입점을 추가했다. 사용법과 실제 실행 제약은 [Codex 환경](codex-setup.md)에 있다.
- 기존 프론트 초기 화면을 확장하는 작업이 진행 중이다. 홈/티켓형 수집판/미션 카드/인증 화면/대표 소원 화면이 있으나 **Taste 적용 전에 작성한 초안**이며 확정 디자인이 아니다.
- 초안은 `npm run lint`, `npm run build`를 통과했다. 브라우저/사용성 검증 전이므로 UI 페이즈를 완료 처리하지 않는다.
- Taste 원본 정적 lint도 실행했고 FAIL을 확인했다. 상단 장식 라벨/번호/장식 기호/정지 그림자 등이 지적됐다. 적용할 앱 화면 절차를 읽고 해당 화면 규칙으로 개선/재검사해야 하며 기존 ESLint 성공을 Taste 통과로 기록하지 않는다.
- 일반 로그인/가입/비밀번호 관리 API는 아직 없다. 프론트 초안의 입력 확인은 실제 자격증명을 전송/저장하거나 세션을 만들지 않는다.
- 로컬 브라우저 inspector는 Chromium socket 권한, Playwright CLI는 캐시/설치 부재로 실행이 막혔다. 다음 UI 작업에서 사용 가능한 브라우저 도구 또는 실행 가능한 환경으로 전후 캡처와 검사를 해야 한다.

## 2026-11-03 — UI 개선

- Taste 앱 절차로 밝은 단일 강조색 방향을 선택하고 홈 수집판/미션 목록/인증/대표 소원 화면을 재구성했다. 홍보 장식과 가짜 티켓 번호를 제거하고 두 S를 구분했다.
- 상태 전환 링크 버그, 첫 오류 포커스, 인증 단계 아이디 수정/비밀 입력 초기화, 목적별 제목과 직접 경로 안내를 보완했다.
- 단위 테스트 8개, ESLint, 운영 빌드와 Taste 앱 정적 검사(0 FAIL/0 WARN), 스킬 해시 검사를 통과했다.
- Playwright를 테스트 전용 정확 버전으로 고정했다. CI에서 운영 5개 폭과 개발 입력/팝업/미리보기 배제를 검사하고 스크린샷을 저장하도록 추가했다.
- 로컬 브라우저는 Chromium socket 권한/다운로드 실패, 대체 브라우저의 로컬 접속 거부로 차단됐다. CI 결과/스크린샷 검토 전 페이즈 1 완료로 표시하지 않는다.
- 구체 결정/재현 명령/검사 범위는 [UI 검수](ui-review.md)에 있다. 서버 인증/DM/저장 등 이후 페이즈는 계속 미구현이다.

- Taste 운영 렌더 검사는 0 FAIL/1 WARN이었다. 모바일 13px 미만 문구 비율 경고에 따라 수집 라벨/설명/미션 설명/상태를 13px로 높였다. 최종 결과는 PR의 현재 커밋 checks와 frontend-ui-review 아티팩트가 기준이다.
- 이 완료는 페이즈 1의 프론트 UI 범위다. 실제 인증/DM/태그 해금/검수/글자 지급/저장은 이후 페이즈에서 구현해야 한다. 탐색/마이페이지는 준비/로그인 안내이며 완성된 도메인 화면이 아니다.

1. UI 병합 후 페이즈 2 인증을 시작한다. 비밀번호 정책/해시 비용과 Mattermost 실제 권한을 확인하고 purpose별 6자리 DM 인증을 연결한다.
2. 태그 해금과 서버 수집판을 붙일 때 개발 fixture 대신 서버 응답을 사용한다. 프론트의 주소/상태를 인가 근거로 사용하지 않는다.
3. 실제 휴대전화의 NFC/QR, 모바일 키보드/안전 영역, 현장 네트워크는 기능 연결 후 실기기에서 검증한다. 이번 CI의 Chromium 검사는 실기기 검사를 대신하지 않는다.

## 2026-11-04 — 페이즈 2 착수

- 실제 MySQL/Redis의 일회성·버전 경합·롤백·세션 검사와 어댑터 단위 테스트를 추가했다. 실행 결과는 아직 확정하지 않았다.

- 실제 Mattermost 토큰/지정 채널 권한은 검증하지 않았으며 실제 DM 발송을 수행하지 않았다.
