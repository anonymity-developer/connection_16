## 구현

- **SHOW ME:** 기존 필수 MM 정보/닉네임/소개/관심사/현재 동의·공개 검증은 그대로 사용한다. 프로필 저장 시 OPEN이면 자동 지급한다. 별도 `POST /api/v1/missions/show-me/reconcile`은 인증·CSRF·principal version 검증 후 동일 완료 서비스로 처리한다. GET은 쓰기를 하지 않는다. 현재 사용자의 row lock과 기존 evidence/진행/완성 순번 트랜잭션을 재사용한다. 기존 완료는 그대로 두며, 다른 네 미션의 NFC 해금은 유지한다.
- **사전 등록:** 기존 `profile_preparation_enabled`가 켜져 있고 BEFORE_OPEN일 때만 저장 가능하다. 행사 전/미설정/종료 상태에서는 S를 새로 지급하지 않는다. OPEN 후 로그인/페이지 이동/참여 기록 갱신 시 재확인 POST를 보낸다. 페이지를 계속 열어두기만 한 사람에 대한 시각 예약 배치는 만들지 않았다. 지급 시각·evidence 인정 시각은 실제 처리 시각이며 프로필 저장 시각/행사 시작 시각으로 소급하지 않는다. 완료 순번은 기존 최종 완료 트랜잭션이 배정한다.
- **동시 갱신:** 재확인 결과가 `newlyCompleted=false`여도 서버 수집판을 다시 읽는다. 다른 탭이 먼저 지급한 결과를 이전 LOCKED 스냅샷으로 덮지 않는다.
- **기존 SHOW 태그:** 유효한 과거 태그는 프로필로 안내하며 해금 기록을 새로 만들지 않는다. 서버가 프로필 조건을 확인해야 지급할 수 있다. 토큰/태그 조회 보안은 유지한다. 새 NFC 준비 도구는 다른 네 미션의 태그만 만든다. 기존 운영 태그를 삭제/비활성화하지 않는다.
- **SYNC ME:** 실제 최초 결과 화면의 `나와 통하는 동료 만나기`는 기존 `/discovery` 추천 탭으로 이동한다. 추천 없음/오류/공개 범위는 기존 화면이 처리한다. 추천 API, 설문 버전·유형 계산, 최초 결과·S 지급, 그래프 가중치는 수정하지 않았다.
- **MAKE A WISH:** 실제 submit fulfilled 응답 뒤에만 동전·작은 호수 물결 CSS 연출을 표시한다. 제출 실패/단순 재조회에는 표시하지 않는다. 동일 revision 응답은 한 화면에서 한 번만 연출한다. 텍스트로 접수와 검수 상태를 설명하고 첫 승인 후 A임을 명시한다. 동기 ref로 같은 순간 중복 제출도 막되 기존 pending key/payload·불확실 응답 재시도·수정 버전 처리는 유지했다. reduced-motion에서는 정적인 그래픽으로 전환한다. 운 점수/낙하 구역·승인 여부를 읽어 연출하지 않는다.
- **SAY 파이팅!:** 이름과 `SSAFY 동료에게 따뜻한 응원을 전해요.`를 사용자 카탈로그/홈에 반영했다. 상세·힌트·수집판 접근성 이름은 같은 카탈로그를 사용한다. `SAY_SOMETHING`, Y, `/missions/say-something`, DB/API 기록·응원 검수·하트는 그대로다.
