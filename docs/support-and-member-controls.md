# 오류 신고와 관리자 계정·글자 조정

운영 날짜는 변경하지 않는다. 행사 전 테스트 계정 정리는 계정별 비활성화로 수행한다. 실제 참가자 계정을 자동으로 정리하거나 전체 계정을 한 번에 변경하지 않는다.

## 오류 신고

공통 참가자 헤더의 **오류 신고**에서 로그인한 계정이 최대 200 Unicode code point의 내용을 보낸다. 신고자 ID·아이디·닉네임·접수 시각은 서버가 결정한다. 클라이언트의 신고자 지정은 거절한다. 신고 당시 아이디/닉네임을 보관하므로 계정 비활성화 후에도 관리자에게 신고자를 표시한다.

현재 페이지 경로만 저장한다. 쿼리/해시를 제거하며 NFC `/t/{token}`은 `/t/[tag]`로 대체한다. 비밀번호·쿠키·환경변수·로그를 자동 첨부하지 않는다. 비로그인 상태에서는 로그인을 안내한다.

| API | 조건·응답 |
| --- | --- |
| `POST /api/v1/error-reports` | 로그인·CSRF·Idempotency-Key 16~64자. `{body,pagePath}` → `{id,createdAt}` |
| `GET /api/v1/admin/error-reports?offset=0&limit=25` | 현재 ADMIN. `{items,total,offset,nextOffset}`; 최신 접수부터 조회 |

계정당 10분에 신규 5회로 제한한다. 같은 키·내용·경로는 원래 접수 결과를 반환하고 중복 저장하지 않는다. 같은 키의 다른 내용은 409다. 관리자 메뉴 **오류 신고**에서 내용·신고자·접수 시각·경로와 이전/다음 페이지를 확인한다. 신고 상태 변경·담당자·댓글 기능은 포함하지 않는다.

## 계정 비활성화

관리자 **참가자 → 상세 → 계정·글자 조정 → 계정 비활성화**에서 사유와 `비활성화` 확인을 입력한다.

- ACTIVE 참가자 USER만 대상이며 관리자 계정은 변경하지 않는다.
- 이전 참여/글/댓글/반응/프로필/관계·전체 완료 기록을 보관한다. 현재 게임 슬롯·완료 근거·완료 순번·태그 해금과 공개 관계를 제거하고 글/댓글·탭 시도를 보관 상태로 전환한다. 다른 참가자의 독립 글/게임은 유지한다.
- 이전 프로필을 비공개로 바꾸고 기존 접속 세션을 종료한다. WITHDRAWN 상태와 credential version 증가로 오래된 인증도 거절한다.
- 이전 외부 식별자와 아이디를 관리자 전용 account_deactivations에 보관하고 users의 외부 연결/아이디 유일성 자리를 해제한다. 다른 기존 사용자와 합병하거나 비밀번호를 복사하지 않는다.
- 같은 Mattermost 계정으로 DM 인증 후 재가입하면 새 user ID를 발급한다. 프로필·동의·태그·글자·게임·동료 관계를 이어받지 않는다. OPEN 중 프로필 요건을 갖추면 첫 S부터 다시 획득한다.
- 관리자 목록/상세에서 이전 아이디·비활성 상태·조정 이력을 확인한다. 현재 가입/접속 집계와 공개 프로필·게임 순위에는 제외한다. 보관 기록 복원은 제공하지 않는다.

`POST /api/v1/admin/members/{id}/deactivate`:

```json
{"expectedGeneration":0,"action":"DEACTIVATE","reason":"행사 전 개발 테스트 계정 정리","confirmation":"DEACTIVATE"}
```

## 글자별 조정

`POST /api/v1/admin/members/{id}/missions/{missionCode}`의 미션 코드는 SHOW_ME/SYNC_ME/MAKE_A_WISH/FAST_TAP/SAY_SOMETHING이다.

```json
{"expectedGeneration":0,"action":"REVOKE","reason":"오류로 인한 해당 게임 재참여","confirmation":"APPLY"}
```

| action | 결과 |
| --- | --- |
| UNLOCK | 해당 미션 해금. 기존 획득·게임 결과 유지 |
| GRANT | 해금과 획득 부여. ADMIN_ADJUSTMENT 근거를 기록하며 실제 점수/글/성향 결과는 만들지 않음 |
| REVOKE | 해당 게임을 보관 후 초기화하고 획득 취소. 기존 해금 유지, 재참여 가능 |
| LOCK | 해당 게임 참여/획득 초기화와 해금 취소. 실제 NFC 태그로 다시 해금 가능 |

첫 S는 NFC가 필요하지 않으므로 UI에서 UNLOCK 버튼을 사용하지 않는다. SHOW_ME 취소/잠금 후 자동 reconcile의 즉시 재지급을 막는다. 참가자의 명시적 프로필 재저장이나 관리자 GRANT로 재지급을 허용한다. 프로필 내용/동의는 유지한다.

SYNC 취소는 현재 성향 결과/접수 projection을, TAP 취소는 공식 슬롯을, A/Y 취소는 해당 글 슬롯을 비운다. A 취소는 본인의 이전 소원 댓글도 보관 처리한다. 다른 미션과 독립 하트/동료 관계는 유지한다. 기존 네 게임 초기화와 계정 비활성화는 각자의 범위를 적용한다.

획득을 취소하면 현재 전체 수집 완료 순번도 취소한다. 다시 5종을 모으면 새 순번을 부여하며 전역 sequence를 되감지 않는다. 수동 지급은 운영상 수집 상태에 반영하지만 실제 수행을 재검증하는 시상 근거로는 인정하지 않는다.

## 보관·동시성

관리자 변경에는 현재 ADMIN·CSRF·Idempotency-Key와 사유/확인이 필요하다. 관리자/참가자 행을 ID 오름차순으로 잠근 뒤 상태·권한을 재확인한다. 현재 참여 snapshot·조정 이력·감사·상태 변경은 같은 트랜잭션이며 함께 롤백한다. snapshot에 비밀번호 해시/인증 비밀값을 넣지 않으며 응답에도 원본을 내보내지 않는다.

game_participation_resets에 operation/mission_code를 추가해 네 게임 초기화와 글자 조정/비활성화를 같은 세대로 직렬화한다. 관리자 상세 최근 10건과 감사 이력에서 범위를 구분한다. 같은 키·대상·이전 세대·동작·미션·사유는 원래 결과로 재시도하며 다른 내용은 409다.

모든 조정이 resetGeneration을 증가시키므로 변경 전 열린 게임의 지연 제출은 기존 X-Participation-Generation 검사로 409를 받는다. 첫 S 취소는 프로필 version도 증가시켜 조정 전 폼 저장에 의한 재지급을 막는다. 비활성화와 경합한 변경은 ACTIVE/version 확인에서 차단한다.

V15는 신고/비활성화 연결/첫 S 재지급 차단 테이블과 조정 범위 컬럼·감사/접수 종류를 추가한다. 적용된 이전 마이그레이션을 수정하지 않는다. 검증·실제 적용 여부는 [개발 현황](progress.md)을 따른다.
