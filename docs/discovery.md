# 동료 탐색·프로필 상세·발견 관계 — 페이즈 5-1

닉네임 중심 목록 → 명시적 프로필 열기 → 최초 방문 → 내 관계/통계를 연결한다. 기존 V1 `profile_views`를 실제 사용하며 탐색 최초 구현은 새 DDL 없이 시작했으며 프로필 가져오기 변경은 V9를 사용한다. 정확한 DTO는 [탐색 OpenAPI](discovery.openapi.yaml), 코드 시작점은 DiscoveryController/Service/Repository다.

## 현재 범위와 남은 일

목록/검색/필터/추천, 상세, 최초 방문, 내 방향 그래프/통계와 모바일 화면을 구현한다. 승인된 비익명 소원·응원/공개 설정 댓글의 프로필 링크도 연결한다. 익명 작성자를 추론하는 추천/링크는 만들지 않는다.

관리자 수동 검수·공개 관리·감사는 구현했다. 신고와 외부 자동 검수는 후순위다. 개인별 차단, 회원 제재 API, 추가 추천 고도화, 시상 정산, 종료 후 공개 유지 정책과 실기기/부하 검증은 후속이다. 현재 계정 제재는 기존 users.status의 ACTIVE/SUSPENDED/WITHDRAWN 필터이며 개인 간 차단 기능을 구현한 것으로 해석하지 않는다. 외부 제공자 호출/DM/배포/운영 DB 변경은 수행하지 않는다.

## 세션·동의·공개 조건

모든 탐색 API는 로그인 세션과 유효한 현재 공개 프로필/두 동의를 확인한다. 본인 조건이 부족하면 409 PROFILE_REQUIRED다. 미션 태그 해금은 탐색의 추가 조건이 아니다.

대상 계정은 ACTIVE, Mattermost 가져오기 완료, 이름/지역/양수 반/닉네임과 현재 두 안내 확인이 필요하다. 소개/관심사/링크는 비어도 된다. profile.is_public=true는 레거시 호환용 내부 조건이며 새 저장은 항상 공개다. 참가자 비공개 기능은 없다. [가져오기 계약](mattermost-profile.md)을 따른다. 같은 SQL 조건을 목록/추천/상세/그래프/통계에 적용한다. 정지·탈퇴·비공개·불완전·예전 동의만 있는 계정은 제외한다. 목록에서 발견했던 ID도 상세를 열 때 다시 확인한다. 대상이 없거나 현재 공개할 수 없으면 같은 404 PROFILE_NOT_FOUND다.

목록/추천/관계/통계는 현재 공개 조건이 맞으면 행사 전후에도 읽을 수 있다. 실명/반을 반환하고 방문을 저장하는 POST open은 현재 OPEN 기간에만 허용한다. 기존에 방문한 대상이나 본인 상세를 다시 열 때도 OPEN 검사를 유지한다. 행사 종료 뒤 상세 열람 유지 여부는 운영 확정 전까지 이 제한을 기본으로 한다. 내 원본 프로필 확인/수정은 기존 `/users/me/profile` 계약을 따른다.

## 공개 DTO와 상세 경계

Person은 id/닉네임/관심사/선택적인 성향 유형/본인과의 공통 관심사/동일 유형 여부/방향 방문 플래그만 반환한다. 목록에 실명, 반, 소개, 외부 링크, Mattermost ID/username, 인증/동의 원문, 성향 답안/축 점수는 넣지 않는다. 성향 유형은 저장된 결과와 그 결과의 문항 버전에서 읽으며, 유형 정의가 유효하지 않으면 임의 유형을 만들지 않고 type=null로 표시한다.

상세 정보는 POST `/discovery/profiles/{id}/open` 성공 응답에만 포함된다. GET 상세 우회 경로는 없다. 세션 사용자가 조회자이며 body의 viewerId/visited/역할 등은 사용하지 않는다. 상세는 Person과 Mattermost 이름/지역·반/사진 URL, 선택 소개/GitHub/블로그, 신규 방문 여부다. 가져온 이름은 독립적으로 검증된 법적 신원으로 표현하지 않는다. 사진은 상세 방문 후에만 자체 GET 프록시에서 내려준다.

외부 링크는 서버와 브라우저 모두 HTTPS·정상 host·사용자 인증정보 없는 URI만 허용한다. 새 탭 링크는 noopener/noreferrer를 설정한다. 본문/닉네임은 HTML로 해석하지 않는다. 프로필 응답/오류를 공유 캐시하지 않으며 기존 Spring Security no-store 헤더를 유지한다. 브라우저 영구 저장소에 상세 정보를 보관하지 않는다. 문서 제목에도 실명/닉네임을 넣지 않는다.

## 목록·추천

GET `/discovery/people`와 별칭 GET `/profiles`는 같은 닉네임 목록을 반환한다. 본인은 제외한다.

| 조건 | 현재 계약 |
| --- | --- |
| cursor | 양수 사용자 ID 미만, ID 내림차순. 생략 시 처음 |
| limit | 기본 20, 1~30 |
| q | 입력 전체 최대 30 UTF-16 code unit, 검색 시 앞뒤 공백 제거. 닉네임만 검색, `%`, `_`, `!`는 일반 문자로 처리 |
| interestId | 양수 관심사 ID. 해당 관심사가 없으면 빈 목록 |
| typeCode / questionnaireVersion | 둘 다 주거나 둘 다 생략. 대문자 1~4자 유형 코드와 1~64자 버전. 다른 버전의 같은 문자를 같은 유형으로 묶지 않음 |

다음 페이지가 있으면 마지막 반환 ID를 nextCursor로 준다. 검색/관심사/브라우저 뒤로가기를 URL에 반영한다. 검색 조건이 바뀐 뒤 이전 요청이 늦게 돌아와도 새 결과를 덮어쓰지 않는다. 더 보기 중 새 검색을 해도 이전 로딩 상태를 이어받지 않는다.

GET `/discovery/recommendations`는 최대 12명을 weighted-v2 합산 점수순으로 반환한다. 관심사 합집합 대비 공통 비율 최대 30점, 동일 버전 유형 20점, 소원 댓글 15점, 응원 하트 10점, 미방문 20점, 다른 지역·반 5점을 더한다. 동점은 조회자·정책 버전·선택적 seed에 따른 고정 해시로 정하며 seed 변경은 점수를 바꾸지 않는다. 익명 교류는 내부 계산에만 반영하고 기존 Person DTO/공개 그래프에 점수나 교류 신호를 추가하지 않는다. SQL에서 상위 ID를 정한 뒤 선택된 프로필만 묶어서 읽는다. [계산·동점·공개 경계와 검사 설계](recommendation-design.md)를 따른다.

관심사는 SQL에서 페이지별 묶음으로 읽고, 선택적인 유형 정의도 한 페이지에서 버전별로 파싱해 재사용한다. 사람마다 별도 프로필/성향 API를 호출하지 않는다. 실제 운영 성능은 부하 검사로 별도 검증해야 한다.

## 최초 방문과 계정·자격 변경 경합

1. 조회자/대상 사용자 ID를 중복 제거하고 오름차순으로 SELECT FOR UPDATE한다.
2. 본인 세션 버전/현재 공개 자격/행사 기간과 대상 공개 조건을 확인한다. 사용자 잠금 전에 일반 읽기로 오래된 프로필 snapshot을 만들지 않는다.
3. 본인 방문은 행을 만들지 않는다. 그 외 `(viewer_id,viewed_id)` 기존 행을 확인하고 없을 때만 DB UTC 시각으로 삽입한다. PK가 최종 중복 방어다. 제약 오류를 일반 성공으로 숨기는 INSERT IGNORE는 사용하지 않는다.
4. 같은 트랜잭션에서 현재 관계와 상세를 반환한다. 신규 저장 후 오류가 나면 방문도 롤백한다.

자연 키가 있으므로 별도 Idempotency-Key 없이 POST 재전송을 받아도 최초 행/시각을 유지한다. first_viewed_at은 서버 저장 시각이며 네트워크 도착 순서나 물리적으로 만난 증거가 아니다. 상세를 브라우저에서 새로고침해도 조회수·미션 글자가 늘어나지 않는다.

계정 제재/자격 변경도 같은 사용자 잠금 순서를 사용한다. 제한이 먼저 커밋됐다면 상세나 새 방문을 만들지 않는다. 참가자 공개 철회 API는 제거했다. 과거 비공개/미완성 계정은 필터링하며 방문 원장은 지우지 않는다. 사진은 외부 다운로드 후 자격을 재검사한다. 이미 전달한 응답을 회수하는 기능은 아니다.

## 내 발견 그래프와 통계

GET `/discovery/graph?limit=...`는 본인 Self, 현재 공개 가능한 직접 상대 Person과 방향 Edge만 반환한다. 기본 20/최대 30명이며 상호 방문 → 내 유효 공개 응원 하트 → ID 내림차순으로 제한한다. 내→상대와 상대→내를 구별하고 둘 다 있으면 mutual=true다. 상대들 사이의 별도 방문 관계는 반환하지 않는다. 제한 밖 상대가 있으면 truncated=true다.

GET `/discovery/stats`는 현재 공개 조건을 만족하는 전체 상대의 visitedCount/visitorCount/mutualCount다. 그래프 limit과 독립적이며 본인 방문과 비공개 상대는 세지 않는다. 별도 합계 테이블/상호 방문 플래그를 중복 저장하지 않고 원래 방향 행에서 계산한다.

그림은 화면 너비에 맞게 강한 관계부터 배치한다. 아래 목록은 30명씩 offset으로 더 읽는다. 페이지 사이에 실제 관계가 바뀌면 순서가 달라질 수 있으며 새로고침으로 다시 읽는다. 화살표는 프로필을 연 방향이고 전체 닉네임/관계는 목록에서 확인한다. 0은 실제 0으로 표시하며 로딩/오류를 0이나 가짜 인물로 대체하지 않는다. 이 관계는 친구 수/수상 순위가 아니라 프로필 열람 관계다.

## 공개 콘텐츠의 프로필 링크

PublicContent와 PublicComment에 profileId nullable 필드를 추가한다. 소원·응원은 승인된 revision의 anonymous=false, 댓글은 승인된 revealProfile=true이며 현재 작성자가 공개 가능한 경우에만 실제 작성자 프로필 ID를 반환한다. 익명일 때는 nickname/profileId가 null이다. 원본 item/comment ID로 프로필 ID를 추측하거나 대체하지 않는다.

UI는 공개 플래그와 profileId를 함께 확인해 `/discovery/profiles/{id}`로 이동하고, 그 화면이 CSRF POST open을 수행한다. 링크 hover/목록 조회로 상세나 방문을 미리 만들지 않는다. 작성자가 익명 설정을 수정 중이면 기존 승인본의 설정을 유지하고, 새 revision이 승인된 뒤에만 링크가 전환된다. 계정·현재 안내·가져오기 완료 조건은 모든 공개 조회에서 다시 필터링한다.

## 검증과 운영 한계

실제 MySQL/Redis 통합 검사로 DTO 분리, 현재 동의/상태/프로필 필터, 문자열 검색/커서, 결과 버전, 동시 최초 방문/시각 유지, 사용자 잠금과 자격 변경, 저장 롤백, 본인/상호/직접 관계/상한/전체 집계, 기간/세션/CSRF/GET 우회/위험 URL을 확인한다. 기존 콘텐츠 검사에는 승인된 익명 설정에 따른 profileId 전환도 추가한다.

브라우저 계약 대역으로 로그인 게이트/5개 폭/검색·뒤로가기·지연 응답/상세 POST/재시도·복원/비공개 전환/외부 URL/관계/빈 상태와 공개·익명 링크를 검증한다. 실제 참가자나 방문을 만들지 않으며 외부 Mattermost/실기기·현장 네트워크/운영 부하·배포 검증과 구분한다.

## 관계 가중치 v1 (feat/network-graph)

Edge에 weight(1~6), strength(LIGHT/MEDIUM/STRONG)를 추가한다. 방향별 방문 1점, 상호 방문 추가 2점, 내가 누른 승인된 비익명 응원 하트 2점이다. 기존 방문 간선/후보 범위를 유지하며 취소 후 재등록은 누적하지 않는다. 익명 소원·댓글과 상대방의 하트 신원은 반영하지 않는다. 점수는 조회자 관점이다. 동료 탐색의 나의 발견 관계 화면에서 그림 및 노드 이동을 제공한다. 상세 근거와 제약은 [작업 보고](network-moderation-handoff.md)를 따른다.

## 2026-11-10 알고리즘 선택과 검증 범위 (당시 기준)

아래 추천 순서는 당시 기록이며 현재 weighted-v2 가산점 설계로 대체됐다. 공개 그래프의 별도 관계 점수는 유지한다.

- 추천 후보는 기존 공개 자격을 통과한 본인 외 계정이다. 미방문, 공통 관심사 수, 동일 버전 유형의 순위를 유지하고, 동률에서 지역·반 조합과 ID를 비교한다. 지역과 반은 목록에 반환하지 않는다. 가중합은 서로 다른 근거 사이의 교환 비율이 필요해 보류했다. 유형 결과가 없으면 불일치와 같은 우선순위다.
- 그래프에서 ID로 먼저 자른 뒤 하트를 조회하면 오래된 강한 연결을 놓친다. 현재 후보 전체에서 상호 여부와 유효 하트 존재 여부를 먼저 정렬한다. v1 점수는 단방향 1/3, 상호 4/6이므로 이 순서는 점수순과 같다. 각 방향은 화살표 하나이며 두 방향의 점수를 더하지 않는다. 댓글 및 타인이 누른 하트는 제외한다. 유효 승인본이 바뀌거나 하트가 삭제되면 다음 조회에 반영된다.
- 그래프 페이지당 저장소 SQL은 최대 2회에서 1회로 바뀌었다(세션·자격·본인 프로필 조회 제외, 코드 경로 기준). 후보를 C명이라 하면 비교 정렬의 상한은 O(C log C)이며, SQL의 실제 비용은 상관 서브쿼리와 인덱스·실행 계획에 따라 달라진다. 저장소가 읽는 결과 행은 최대 limit+1개다. 시간·연결률 개선은 측정하지 않았다.
- 고정 원형은 단순하지만 좁은 화면에서 글자 폭을 고려하지 않는다. 힘 기반 배치는 반복 계산과 위치 변동이 있어 채택하지 않았다. SVG와 링크를 유지하고 직접 간선을 한 번 색인한 뒤 강도·ID 순으로 선택한다. 반경, 라벨 여백과 인접 현의 최소 길이로 표시 수를 정한다. 노드 V개, 간선 E개에서 O(E+V log V) 시간, O(V+E) 보조 공간. 읽지 않은 페이지는 사용자가 목록에서 요청한다.
