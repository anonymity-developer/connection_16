# 관리자 콘솔 — 페이즈 5-3

오류 신고 목록과 계정 비활성화·글자별 해금/획득 조정은 [운영 지원 계약](support-and-member-controls.md)을 따른다. 기존 네 게임 초기화와 별개의 범위이며 모든 변경은 사유·확인·보관·감사를 남긴다.

현재 콘텐츠 메뉴는 기본적으로 검수 없이 공개된 글의 숨김/복구와 감사 이력을 제공한다. 참가자 상세의 **게임 참여 초기화**는 한 명의 네 게임을 초기화하며 계정·프로필·첫 S·기존 태그 해금은 유지한다. [현재 공개·초기화 계약](direct-publication-and-reset.md).

`main`의 콘텐츠 검수 기능에 독립 관리자 로그인, 참가자/접속 분석, 미션별 순위와 관리자 전용 미리보기를 추가한다. main의 잠정 시상 후보·행사 결과 화면도 연결한다. 최종 수상자 확정은 포함하지 않는다.

작업 브랜치는 원래 `connection_16` 저장소의 `feat/admin-page`다. 기존 PR 브랜치와의 충돌 점검은 [호환성 확인](admin-pr-compatibility.md)을 따른다.

## 계정 등록과 로그인

서버 환경변수에 `ADMIN_BOOTSTRAP_ID=admin:tagme`, `ADMIN_BOOTSTRAP_PASSWORD`(운영자가 정한 15~64자), `AUTH_HMAC_KEY`(32바이트 이상 난수의 Base64)를 설정한다. 기본/공용 비밀번호는 없다. 아이디는 `admin:` 뒤 소문자 영문/숫자/`.`/`_`/`-` 1~48자다. `:`는 참가자 Mattermost username 문법 밖이라 두 계정 영역이 충돌하지 않는다.

서버 시작 시 `local_admin_accounts`와 `user_credentials`에 계정과 해시를 등록한다. 실제 Mattermost 계정/참가자 프로필은 만들지 않는다. 두 bootstrap 값을 모두 비우면 새 계정을 만들지 않고 기존 계정은 유지한다. 같은 아이디에 다른 비밀번호를 설정하고 재시작하면 해시/credential version을 갱신해 기존 세션을 차단한다. 정지·권한 회수된 운영자를 bootstrap이 자동 복원하지 않는다. 비밀번호는 서버 환경변수에만 보관하며 Git·로그·브라우저 설정에 넣지 않는다.

기존 `/auth`의 동일한 아이디/비밀번호 폼에서 로그인한다. `POST /api/v1/auth/login`이 `admin:` 계정만 별도로 검증하며 Mattermost API·DM은 호출하지 않는다. 참가자 인증은 기존 경로를 유지한다. `AUTH_ENABLED=false`여도 관리자 로그인은 가능하고 HMAC 기반 시도 제한, CSRF, 세션 ID 교체, Redis 세션과 현재 DB 역할/credential version 검사를 적용한다.

다른 브랜치의 로컬 스택과 함께 실행할 때는 `.env`의 `COMPOSE_PROJECT_NAME`과 `WEB_PORT`/`API_PORT`/`MYSQL_PORT`/`REDIS_PORT`를 별도로 정한다. 해당 작업 공간에서 `docker compose -f compose.yml -f compose.dev.yml --profile app up -d --build --wait`로 실행한다. 관리자만 확인하려면 Mattermost 설정은 필요하지 않다.

사용자 응답에 `admin`이 추가되어 관리자 로그인은 `/admin`으로 이동한다. UI 플래그 자체가 권한은 아니다. `/auth/config`의 기존 필드 외에 `participantAvailable`, `adminAvailable`이 추가된다. `available`은 둘 중 하나가 준비됐다는 뜻이고 DM 요청은 `participantAvailable`을 사용한다.

## 화면과 API

요청·응답 스키마는 [관리자 OpenAPI](admin.openapi.yaml)를 따른다. 로그인 응답은 기존 [인증 OpenAPI](auth.openapi.yaml)에 포함한다.

아래 API는 `/api/v1` 접두사와 유효한 서버 ADMIN이 필요하고 no-store다. 인증/비밀번호/외부 ID는 응답하지 않는다.

| 화면 | 읽기 API | 내용 |
| --- | --- | --- |
| `/admin` | `/admin/overview` | 가입/유효 계정/전체 완료/접속 세션 수, 다섯 미션 해금·참여·완료 |
| `/admin/members` | `/admin/members?offset=0&limit=25&q=...` | 가입 순서, 이름/닉네임/아이디/지역·반, 시각, 미션 수, 접속 시간 |
| `/admin/members/{id}` | `/admin/members/{id}` | 상세 프로필·관심사·링크, 미션별 결과와 최근 접속 30건 |
| `/admin/rankings` | `/admin/rankings/{mission}?offset=0&limit=25` | 미션별 현재 유효 순위와 계산 기준 |
| `/admin/completions` | `/admin/completions?offset=0&limit=25` | 기존 운영상 전체 완료 순서 |
| `/admin/preview` | `/admin/preview/sync` | 미리보기용 문항 정의와 EXAMPLE/CONFIGURED 구분 |
| `/admin/moderation` | 기존 검수/콘텐츠/감사 API | 기존 승인·거절·재처리·숨김·복구·감사 |
| `/admin/moderation?tab=awards` | 기존 시상 후보 API | 잠정 후보·동점·중복 후보 검토 |
| `/admin/moderation?tab=results` | 기존 행사 결과 API | 행사 집계·제한된 참여 내역·내보내기 |

위 화면은 모두 같은 관리자 틀을 사용한다. 좌측 메뉴·헤더·로그아웃과 휴대폰 메뉴는 페이지 이동 중에도 유지한다. 검수의 콘텐츠/감사 이력은 내부 탭이며 시상 후보/행사 결과는 공통 메뉴에서 이동한다. 이동 때 현재 세션과 서버 ADMIN을 재확인하며 확인 중에는 비공개 내용을 제거한다.

목록은 offset 0~100,000, limit 1~50(기본 25), `{items,total,offset,nextOffset}`를 사용한다. 검색은 최대 64자로 이름/닉네임/아이디에 적용하고 `%`, `_`, `!`를 문자로 취급한다. 가입 순서는 검색/페이지와 무관하게 `created_at → id`로 계산한다. 제한·탈퇴 계정도 목록에 상태를 남긴다. 독립 운영자는 참가 통계에서 제외하고, 가입 자격증명이 없는 더미/레거시 프로필은 가입자 수에 포함하지 않는다.

SHOW ME는 NFC 없이 소개·관심사와 자격을 갖춘 프로필에 자동 지급한다. 다른 네 미션의 해금은 progress 존재, SHOW ME 참여는 완료, SYNC는 결과 존재, TAP은 공식 슬롯 존재, 소원/응원은 작성 슬롯 존재로 구별한다. 여러 집계/목록을 한 응답에 조합하는 DB 조회는 같은 트랜잭션에서 수행한다.

## 순위

| 미션 | 기준 | 동점 |
| --- | --- | --- |
| SHOW ME·SYNC ME | 완료 시각 오름차순 | 회원 ID |
| FAST TAP | 현재 슬롯의 VALID 공식 탭 수 내림차순 | 제출 시각, 회원 ID |
| MAKE A WISH | 받은 유효 승인 댓글 수 내림차순 | 완료 시각, 회원 ID |
| SAY SOMETHING | 받은 유효 하트 수 내림차순 | 완료 시각, 회원 ID |

해당 미션을 완료한 현재 ACTIVE·가져오기 완료·공개 프로필·두 정책 동의 계정만 포함한다. 소원/응원은 공개 가능한 승인본이 필요하다. 숨김·보류 글, 비유효 게임, 자기 댓글/하트, 비적격 반응 사용자는 제외한다. 소원 지표는 받은 댓글 수이며 댓글 활동상 후보 집계와 다르다.

현재 기록의 관리자 확인용 순위다. 시상 snapshot/중복 수상/최종 확정은 하지 않는다. 전체 완료 화면은 기존 `completion_order`이며 검수 지연을 보정하는 유효 원접수 기반 수상 순위로 표시하지 않는다.

## 접속 시간

V10 `connection_sessions`는 로그인마다 임의 UUID, 사용자/credential version, 시작·최근 요청·유휴 만료·명시적 종료 시각과 종료 사유를 저장한다. 브라우저 쿠키/Redis 세션 ID는 저장하지 않는다. 인증된 요청은 만료 예정 시각을 갱신하고 로그아웃·재로그인·비밀번호 변경·권한 회수는 기존 기록을 종료한다.

시간은 시작부터 명시적 종료까지, 미종료라면 `min(현재, 유휴 만료)`까지다. Redis 만료 이벤트가 누락되어도 무한 증가하지 않도록 조회 때 만료 상한을 적용한다. main 기본 유휴 만료는 4시간이다.

- 사용자가 선택한 로그인~로그아웃/세션 만료 시간이며 실제 화면 집중 시간은 아니다.
- 브라우저를 닫아도 로그아웃하지 않으면 유휴 만료까지 포함한다.
- 동시 기기는 각각 합산하고 현재 접속 수도 유효 세션 수다.
- 도입 이전 기록은 소급하지 않는다. 없으면 `기록 없음`, 측정된 0은 `0시간 0분 0초`다.
- 원장 보관/삭제 기간은 실제 개인정보 정책에 맞춰 별도로 확정해야 하며 현재 자동 삭제하지 않는다.

## 관리자 전용 미션 미리보기

서버 `/admin/access` 승인 뒤에만 마운트하고 포커스 복귀와 30초마다 권한을 재확인한다. 실패하면 화면을 제거한다. 참가자의 기존 태그/정책/기간/1회 제한 API를 면제하지 않는다.

기존 프로필·SYNC·FAST TAP·소원·응원 컴포넌트를 재사용하되 미리보기에서만 별도 React context의 메모리 클라이언트를 제공한다. 이 클라이언트는 `request`/`fetch`를 호출하지 않는다. 실제 계정·프로필·동의·해금·완료·콘텐츠·성향·게임 기록을 바꾸지 않으며 화면 이탈/초기화 시 메모리 상태를 버려 반복 체험한다. 소원·응원·댓글은 미리보기에서도 작성하면 바로 공개되며, 분수·구름·목록과 하트는 메모리 안에서 처리한다. SHOW ME는 닉네임만으로 저장할 수 있지만 소개와 관심사 1개 이상을 채워야 미리보기 S 완료를 표시한다.

`TapMission`/`SyncMission`/`ContentMission`/`ProfilePage`는 참가자 경로와 같은 파일을 직접 import한다. 탭 입력·타이머·설문·소원 분수·댓글·하트 등 프론트 UI와 조작 로직의 변경이 양쪽에 반영된다. 미리보기의 외곽은 관리자 화면이며 기록 안내 문구도 구분한다. 서버의 해금/유효성 판정·점수 계산·검수·저장은 메모리 모형이므로 실제 서버 로직 전체를 같은 조건으로 검증하는 기능은 아니다.

성향은 등록 문항을 쓰고 미등록 상태에서는 `resources/preview/sync-demo.json`의 승인 문항 사본을 **관리자 미리보기 예제**로 표시한다. 미리보기 자체는 예제를 DB의 현재 문항으로 등록하지 않고 실제 동료도 조회하지 않는다. 외부 DM/검수 제공자도 호출하지 않는다.

## 2026-11-10 통합 화면 검수

최신 main `e4692f6` 통합 후 production build의 실제 관리자 DOM을 별도 합성 API 계약에서 캡처해 1440/768/390px로 측정했다. 인증 우회 설정이나 합성 참가자는 제품에 넣지 않는다. 실제 Docker 앱은 기존 관리자 자격증명으로 별도 로그인해 참가자 0명의 정상 빈 상태와 다섯 미리보기를 확인했다. 개발자 도구의 모바일 크기 검사이며 실기기 검수는 사용자 확인이 필요하다.

1. 첫 질문은 “얼마나 가입하고 다섯 미션에 참여했는가?”다. 가입자 수와 미션 참여 표가 먼저 읽히고, 미션 바로 확인 버튼으로 개발 확인을 시작한다.
2. 통계와 표의 좌우 기준선을 맞췄다. 데스크톱 접속 시간 패널은 내용 높이로 끝내 빈칸을 늘리지 않고, 모바일 미션 통계는 동일 폭의 세 열로 배치한다.
3. 기존 DM Sans와 framed-sheet(seed 576897122)를 유지했다. 재추첨 없이 제품 색은 로고·진행 막대에 사용하고, 실제 미션 미리보기 안에서는 참가자 화면의 스타일을 사용한다.
4. 합성 검증 자료의 가입 3명·전체 완료 1명·접속 세션 1개·접속 이력 2명과 7260초(2시간 1분)는 API 대역에만 존재한다. 미션 표의 완료/가입 비율과 숫자를 대조했다. 실제 DB 수치를 이 예시로 대체하지 않는다.
5. 실제 참가자가 없으면 0명, 접속 원장이 없으면 “기록 없음”, 없는 시각은 대시로 표시한다. 모르는 과거 접속 시간을 0으로 만들지 않는다.
6. 다섯 막대는 각각 완료/가입자 비율을 뜻하고 접근성 설명에 분모와 완료 수를 적는다. 해금·참여·완료 숫자는 별도 라벨과 함께 표시한다.
7. 휴대폰 메뉴는 접고 버튼으로 펼친다. 메뉴 이동 후 닫힘, 검색 후 뒤로가기 복원, 내용 넘침 없음, 다섯 미리보기의 작성·반복·초기화를 브라우저에서 확인했다. 태블릿 가로 메뉴는 가로 스크롤로 전체 항목에 접근한다.

## 2026-11-12 미션 확인 후속

참가자 FAST TAP 상위 10명·최고 기록 갱신 소감 컴포넌트를 미리보기에서도 재사용한다. 순위/소감은 현재 관리자 미리보기 메모리 안에서만 계산·저장하며 실제 API를 호출하지 않는다. 초기화는 가상 시도·소감을 함께 지운다. 소원과 응원은 모두 400자·익명/닉네임 선택을 지원한다. 공식 초기화는 기존 시도에 연결된 소감을 보존하고 새 회차에 재참여하도록 한다. [확정 규칙](mission-rules.md).
